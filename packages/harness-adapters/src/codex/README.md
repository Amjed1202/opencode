# Codex App Server adapter — conditional integration

`CodexAdapter` is a host-only implementation exported from `@harness/adapters/codex`. It supports the unmodified Codex CLI **0.153.4** through a private stdio child process. Importing the package or constructing the adapter does not start a process; discovery/preflight/session methods do. No native agent loop is reimplemented.

```ts
import { CodexAdapter } from "@harness/adapters/codex"

const adapter = new CodexAdapter({
  executable: selectedAbsoluteExecutable,
  cwd: selectedAbsoluteWorkspace,
  environment: compiledEnvironment,
  target: { id: "local", kind: "local", name: "Local" },
})
// Use host admission/runtime-manager services before createSession or send.
// dispose() terminates the owned native process when its host shuts down.
```

The host supplies the environment; this package does not import the control plane. The adapter rejects provider keys, URL/profile overrides and all environment names outside its OS allowlist. PATH and home directories must be explicit and fully absolute. Windows HOME and USERPROFILE must agree. Bun on Windows synthesizes some OS variables even for an empty environment object, so home and PATH must be supplied deliberately. Arbitrary parent credentials are not inherited (verified with a nested process fixture). `transportFactory` is a privileged process-supervision injection point, exercised with a real spawned local peer in tests; never expose it to a renderer.

Preflight initializes the pinned protocol with experimental APIs and client attestation disabled, reads `account/read` with `refreshToken:false`, reads effective config for the selected cwd, then reads the account again. It accepts a managed ChatGPT account on a recognized paid plan, an OpenAI provider, and an explicitly acknowledged provider-overage policy. Provider overage remains **unknown**; `require-disabled` cannot pass. API mode, automatic fallback, external auth tokens, native login/logout, purchases and credit resets are not exposed. The user signs in separately using Codex's own flow.

Each native process receives config overrides disabling hooks, plugins, app connectors, host/bundled skill discovery, subagents, shell snapshots, orchestrator MCP/skills, proxy features, login shells, native shell profiles, analytics, feedback and OTEL exporters. The external notification command is forced to an empty array, and the ChatGPT endpoint is pinned to `https://chatgpt.com/backend-api/`. Every requested value must be reflected exactly by native `config/read`. Provider/profile/API/custom endpoint overrides and unverified hook/app settings continue to block execution.

On the first configuration observation, the adapter may replace its child once to clear configured shell values and disable every configured MCP server and plugin. It retains at most 64 names per category, each at most 128 ASCII characters; shell names require environment-variable syntax, and extension names use a restricted character set. Dynamic arguments are bounded to 16 KiB. Shell overrides contain empty strings only; quoted root TOML tables contain extension names and `enabled=false` only. Configured values, commands and credentials never enter replacement arguments. Native table overrides deep-merge, so an empty table alone is insufficient. The replacement repeats version, account and effective configuration checks before any task can be admitted. Every effective shell value must be empty and every effective MCP/plugin entry explicitly disabled; unknown or newly added names fail. Observations are serialized and bounded to 64 pending calls, and disposal or failed replacement prevents dispatch. Established sessions never trigger this restart. All execution methods retain their account/configuration fingerprint revalidation.

These checks use process arguments and read-only native configuration requests; they do not write the user's config or credential files and do not attest OS enforcement. The pinned local config schema defines the notification array and MCP/plugin `enabled` fields. The installed-native readback and fixture results are recorded in [isolation-evidence.md](./isolation-evidence.md).

The policy requires sandboxed shell, denied network, no allowed MCP servers, and read-only or workspace-write filesystem. Every native thread and turn uses **read-only** with network disabled. A host workspace-write policy authorizes review of specific patches; it does not grant a writable native workspace. Ask maps to native **untrusted**, which requests approval before applying a patch; deny maps to **never**, which rejects patches against the read-only sandbox. Thread start/resume checks the returned provider, model, cwd, exact approval policy, user reviewer, read-only sandbox/network fields and idle status. Every turn repeats those settings. Native shell tools are disabled per process with `features.shell_tool=false` and required effective readback: saved native exec-policy allow rules can otherwise bypass the sandbox. Native shell-based file reading and test execution are consequently unavailable; callers must provide selected file context and run repository checks outside the native turn. `requireEnforcedBoundary` must be false. Native account/config evidence is rechecked immediately before creation/resume/dispatch and compared to the host's current admission. Account changes invalidate evidence; routine quota events do not. These observations do not atomically lock native billing or settings against another native client.

The native account schema exposes email and plan, not a stable organization/workspace/account ID. The adapter hashes those fields for correlation and never publishes the email. This detects ordinary account switches but cannot distinguish accounts/workspaces with the same email and plan. Managed native authentication stays entirely inside Codex.

`models(runtime)` implements native `model/list` for the pinned **0.153.4** binding. It requests visible entries, validates the native dispatch string (`model`) and display name, and projects only ID/name/provider with no inferred model capabilities. Pagination is bounded to eight pages, 256 received entries and 128 KiB of projected data; duplicate dispatch IDs, malformed entries, cursor loops and incomplete results fail without returning a partial catalog. Account/configuration observations before and after listing must agree, and account changes during listing invalidate the result.

The desktop loads this catalog when the user checks a ready Codex connection, requires an explicit selection, and issues another native list request before separate billing/policy session admission. There is no automatic selection, manual-ID entry or fallback. A missing selected model or an unavailable catalog blocks creation. Codex may fetch model metadata and write its native cache during listing; another request may return cached data. Catalog membership does not attest entitlement, billing or capabilities, and listing plus dispatch is not an atomic availability check.

The adapter maps turn started/completed/failed, assistant text deltas and authoritative text completion. Thread, turn, item and request IDs are retained independently. Notifications arriving before acknowledgement are buffered and bound only after the native turn ID is returned. Stale or unrelated events are retained as metadata without command attribution. Unknown event bodies, command/error bodies, authentication messages and native stderr are not persisted; unknown event types and safe IDs remain available. This is deliberately lossy redaction, not a raw transcript archive.

Native command and permission-profile expansions offer only deny. A complete observed pending file-change item can offer allow once under workspace-write after canonical path checks; grantRoot and session/workspace grants are rejected. Requests bind native RPC/thread/turn/item identities, policy, workspace lease generation, expiry and an immutable operation hash. File metadata contains paths, kinds and content hashes; no raw patch or command body is persisted. A grant requires fresh native account/configuration evidence and a host-only authorizeReply callback, invoked synchronously at the final stdio write boundary. Expiry, interrupt, close, account changes and changed file evidence cancel pending requests. External-auth, attestation and unsupported tool requests receive an error or explicit decline. Legacy approvals abort. Closing interrupts a known active turn and unsubscribes; it does not delete the native conversation.

Blocking fixed-choice human input is implemented for one to three nonsecret questions with two to eight offered options each. Public events carry generated question/option IDs; exact labels remain private pending data until the host protects and presents them for review. Answers require a current actor-bound review token and a final host authorization callback at native reply time. Free-form, secret, nonblocking and unknown question forms are cancelled. Native resolution, expiry, interruption, account/configuration changes and close retire pending questions without replaying answers.

The transport bounds outbound pending requests (64), concurrent native server requests (32), lifetime native request identities (4096), deferred server replies (65 seconds by default), line size (1 MiB by default), request time (15 seconds by default), pre-ack notifications (128 / 1 MiB), and event backlog (1024 / 4 MiB). Timeout, malformed output and process loss terminate pending work without repeating it. Lost dispatch acknowledgement returns `uncertain`. Backlog overflow emits a gap and stops the owned process. The host journal owns replay and reconciliation. Cleanup currently targets the direct child; descendant-process supervision is a later integration gate.

Read-only inspect uses thread/read metadata and bounded thread/turns/list summaries, with account/config checks on both sides of pagination. Defaults are four pages, 200 turns and 1 MiB; incomplete or changing evidence cannot establish idle; active observations remain running, and malformed or unsupported responses produce unknown state. It returns no message bodies and cannot infer a lost native turn ID from user text. The host can reconcile an exact saved terminal turn separately from resume. Native-ID resume still requires idle state and does not hydrate a transcript.

Chat, streaming, bounded file permissions, blocking fixed-choice input, deny-only expansions, model catalog discovery, history inspection and native-ID resume are tested against pinned generated schemas and local process fixtures. The first authorized live repository attempt exposed an approval defect: native on-request/workspace-write applied a patch without a host request. Native thread creation also persisted project trust. The adapter now uses the stricter settings above; the local byte-level regression first reproduced the old failure and then verified pending/denied files remain unchanged, one explicit accept writes the file, and the next patch requires a new review. These local fixtures do not establish installed-native behavior, private extension implementation or OS enforcement. Updated live acceptance and trust-restoration evidence belong to the repository V1 validation record; the earlier no-prompt startup diagnostic is documented separately in [isolation-evidence.md](./isolation-evidence.md).

Generated types under `generated/0.153.4` are unmodified dependency closures from `codex app-server generate-ts`. `provenance.json` retains file hashes; the official Apache-2.0 LICENSE and NOTICE are included. See [OpenAI App Server documentation](https://learn.chatgpt.com/docs/app-server) and the [pinned official config schema](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/core/config.schema.json).
