The first live Claude input used pushed RC2 source `889ec39` and received a provider weekly rate-limit rejection. An independent reviewer inspected only that task's derived native transcript and task-owned journal/fixture, retaining metadata and byte hashes without raw account data or provider text. [Sanitized evidence](v1-claude-live-rate-limit.json).

The live failure exposed a projection defect: a recognized SDK error with model `<synthetic>` was rejected by ordinary selected-model validation, hiding the rate-limit category. The adapter now accepts only a runtime-checked SDK error enum on a main assistant frame with the expected session/input binding and a null parent. It emits a fixed error category and closes conservatively. Unknown enums, a wrong role, missing or foreign parent, stale input/session and foreign real models still fail closed. Synthetic text, tool blocks, usage and `stop_reason` cannot become successful model output or completion. The targeted regression was observed failing before the correction and passing afterward.

The real adapter/desktop integration regression then exposed a second defect: a consumer paused at an event yield could miss the final journal event when the native pump committed it and ended. A separate deterministic control-plane regression confirmed that the final error was durable but the consumer returned done. Checking for an advanced journal version before checking pump termination fixes the delivery race. It does not change admission, cursor identity, native settlement or replay rules. The adapter author independently reviewed this correction; the control-plane reviewer independently reviewed the adapter correction.

Desktop notices, live activity and saved history use fixed labels derived from error categories. Raw error messages and unrecognized native codes never become display text. The integration test verifies the rate-limit label, unchanged uncertainty, rejected resend/resume, retained saved-history explanation and absence of private synthetic text.
